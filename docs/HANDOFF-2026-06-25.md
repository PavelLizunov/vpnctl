## 1. What the project is

`vpnctl` is a centralized control plane for a small fleet of **sing-box** VPN
exit nodes. A single Rust daemon (`vpnctld`) holds a SQLite inventory, renders
each node's sing-box config, deploys it over SSH, serves an admin UI, and serves
per-user subscription URLs (`/sub/<token>`).

- **Rust workspace:** `crates/{core,crypto,ssh,protocols,kernels,inventory}` +
  `daemon/` (vpnctld) + `cli/`.
- **Inventory DB:** SQLite at `/var/lib/vpnctl/inv.db` on the control host.
- **Source of truth:** GitHub `PavelLizunov/vpnctl` (mirrored to a LAN Forgejo).

## 3. Architecture & the things you must understand

### 3.1 Inventory-first / deploy-second (the #1 source of confusion)

**Every mutation (add user, grant/revoke server, disable, delete) writes ONLY to
`inv.db`. The node sing-box configs are NOT touched until a *deploy*.** A deploy
= re-render the config from inventory + `systemctl restart sing-box`, which
**drops every active connection on that node** (~1-2 s blip; clients reconnect).

- Manual deploy: admin UI **"Deploy all"** / per-server deploy
  (`wizard_bootstrap::run_redeploy` / `run_deploy_all`, SSE).
- **As of this session, `disable`/`enable`/`delete` auto-deploy** the user's
  granted servers in the background (`spawn_user_servers_redeploy` in
  `daemon/src/handlers/admin.rs`). **`grant`/`add` still need a manual Deploy.**
- Consequence: "I deleted/disabled a user but they still connect" was a real bug
  (deleted user kept a cached config until a deploy). Now fixed for
  delete/disable; the operator must still Deploy after add/grant.
- `users_for_server` (the slice that renders node configs) filters
  `WHERE u.disabled = 0` — a disabled user drops out of the rendered config.

### 3.2 Patched sing-box (`1.13.12-userattr`) — MUST be preserved

Upstream sing-box's clash API omits the per-connection `user` field
("NM-11"). We ship a **one-line patch** that adds it so per-user attribution
works off the wire. Recipe: `tools/singbox-attr-patch/` (`clash-user.patch` +
`build.sh` + README).

- Deployed on all 4 nodes, `apt-mark hold sing-box` so apt won't clobber it.
- vpnctl's install gate (`SING_BOX_MIN_VERSION`, `crates/kernels/src/sing_box.rs`)
  sees `1.13.12-userattr ≥ 1.13.12` so `deploy` won't reinstall the stock binary.
- **FOOTGUN:** the installer does NOT build/install the patched binary. A
  freshly-deployed node, or a future `SING_BOX_MIN_VERSION` bump, gets **stock**
  sing-box → loses `metadata.user` → attribution silently drops to ~0 for that
  node. **TODO: wire the patched build into the installer.**

### 3.3 Attribution pipeline

`daemon/src/clash_poller.rs` SSH-curls each node's clash API (`127.0.0.1:9090
/connections`) every **60 s**, reads `metadata.user`, computes **per-connection
byte deltas** keyed by clash connection id, and writes `vpn_connection_stats`.
The server-wide (`user_id IS NULL`) row carries the **unattributed remainder**
(`interval total − Σ per-user`) so `SUM(server-wide + per-user) == true total`.
Coverage is 84–99% (lower on cdn/hysteria2 due to short-lived QUIC connections
that open+close between polls). The old sing-box-log-scraper fallback was removed
this session.

- Billing-grade 100% (v2ray cumulative stats via a Go helper) is **deferred** —
  see `BACKLOG.md`.

### 3.4 Subscriptions & per-server uuids

- `/sub/<token>` renders per-user configs; UA-based format dispatch (v2rayNG,
  Happ→base64, vpn-router → JSON `{status, config}`).
- A user has a **global `users.uuid`** AND optional **per-server
  `grants.client_uuid`** override (a migration artifact: ninitux carried a
  distinct uuid per server). Effective uuid = `COALESCE(client_uuid, users.uuid)`
  (`users_for_server`, `client_uuid_for`). **This override is exactly what caused
  the main-brat collision** (§4.1).
- REALITY params (pbk / short-id / SNI=`www.microsoft.com` / `fp=randomized`) are
  **inbound-level**, identical for all users on a node — only the uuid is
  per-user. So "one user works, another doesn't, same node" ⇒ a uuid problem.

## 4. Known issues / frequent problems

### 4.1 uuid collision — OPEN (repro)

```sql
-- run on 236: sudo sqlite3 /var/lib/vpnctl/inv.db
SELECT g.server_id, COALESCE(g.client_uuid,u.uuid) eff, COUNT(*) n, GROUP_CONCAT(u.id)
FROM grants g JOIN users u ON u.id=g.user_id
GROUP BY g.server_id, COALESCE(g.client_uuid,u.uuid) HAVING COUNT(*)>1;
-- → de | b25684c3-… | 2 | claude-chat-proxy,main-brat
```
`main-brat@de` has `client_uuid = b25684c3` which equals `claude-chat-proxy`'s
global uuid. Symptom: `main-brat` subscription fails to connect on `de` while a
unique-uuid user (e.g. `jokerkis1`) works. The "84 live main-brat connections"
seen in clash are likely `claude-chat-proxy` traffic mis-labeled (shared uuid).
**Fix:** null/replace `main-brat@de.client_uuid` with a unique value → redeploy
`de` → client re-fetches sub. **Also add a collision guard so it can't recur.**

### 4.2 Inventory drift (mostly reconciled this session)

Node configs accumulated "foreign" users (present in sing-box config, absent from
`grants`) from the ninitux migration's partial import. Reconciled de/is/nl/cdn
this session (imported real users as grants, removed orphans). Re-audit:
```sql
-- config-vs-inventory must be reconciled; foreign users would re-appear if a
-- partial import recurs. Compare each node's config uuids to:
SELECT COALESCE(g.client_uuid,u.uuid) FROM grants g JOIN users u ON u.id=g.user_id
WHERE g.server_id='<srv>' AND u.disabled=0;
```

### 4.3 Every deploy = sing-box restart = fleet blip

A config change restarts sing-box (`apply_config` → `systemctl restart`), dropping
all connections on that node. Mass operations generate a wave of "VPN dropped"
complaints. **Do bulk changes in low-traffic hours.** (sing-box has no
connection-preserving reload.)

### 4.4 DPI / RU connectivity

RU TSPU fingerprints REALITY ClientHellos. We switched `fp=chrome → fp=randomized`
(utls "randomized" = fresh ClientHello per handshake). Intermittent DE-from-RU
failures are usually DPI (probabilistic), not server faults. **Stale client
configs still carrying `fp=chrome` must re-fetch the subscription.**

### 4.5 Build toolchain volatility

The Go toolchain used to build the sing-box patch (and sometimes Rust) gets wiped
between sessions / is not on every host. Reinstall as needed (see §6).

### 4.6 Forgejo ⇄ GitHub drift

GitHub `main` got ahead of Forgejo `main`; a build from the stale Forgejo clone
shipped a daemon missing **migration 35** → crash-loop on the prod DB. **Always
build from GitHub `main`; keep Forgejo synced (`git push forgejo
origin/main:refs/heads/main`).**

### 4.7 CI hygiene (green as of d1e9193)

CI runs `cargo {check,test} --workspace --all-targets`, `clippy -D warnings`,
`fmt --check`, `deny`, e2e, gitleaks. It was red for a while because PRs were
merged after only `cargo test -p vpnctld --lib` locally. **Always run the full
`--all-targets` + clippy + fmt before pushing** (see §6). Two tests are
environment/timing-sensitive: `track_1_3_settings_geoip_…` (false-positive when a
geoip DB exists locally; passes in clean CI) and `admin_backup_scheduler_…`
(parallel-timing flake; passes in isolation).

## 6. Build / test / deploy runbook (on `192.168.0.236`)

```bash
ssh user@192.168.0.236
source ~/.cargo/env
# Source already on 236 at ~/vpnctl-gh-build (or: git clone via the proxy).
cd ~/vpnctl-gh-build
export CARGO_TARGET_DIR=/home/user/vpnctl-build/target   # warm cache

# Full CI-equivalent (run ALL of these before pushing):
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo check  --workspace --all-targets
cargo test   --workspace --all-targets   # geoip + admin_backup flakes are env/timing, see §4.7

# Deploy the daemon (control plane only; brief admin-UI blip, no VPN impact):
cargo build --release -p vpnctld
sudo cp -a /opt/vpnctl/vpnctld /opt/vpnctl/vpnctld.bak           # rollback copy
sudo install -m0755 target/release/vpnctld /opt/vpnctl/vpnctld   # (CARGO_TARGET_DIR path)
sudo systemctl reset-failed vpnctld && sudo systemctl restart vpnctld
```

- **Deploy node configs:** admin UI "Deploy all" (or `run_redeploy` per server).
  Restarts sing-box → drops connections. Idempotent — re-renders from inventory.
- **Patched sing-box:** `tools/singbox-attr-patch/build.sh` (needs Go ≥1.25,
  proxy for module fetch) → scp to node → `sing-box check` → backup → install →
  `systemctl restart sing-box` → `apt-mark hold sing-box`. Verify:
  `curl -s 127.0.0.1:9090/connections | jq '.connections[0].metadata|has("user")'`.
- **Git:** commit + push to GitHub `main` (proxy on for the push) AND
  `git push forgejo origin/main:refs/heads/main`.

Useful one-liners (on 236):
```bash
# fleet live activity (last 5 min): users / connections per node
sudo sqlite3 /var/lib/vpnctl/inv.db "SELECT server_id, COUNT(DISTINCT user_id), MAX(active_connections) FROM vpn_connection_stats WHERE ts>strftime('%Y-%m-%dT%H:%M:%fZ','now','-5 minutes') GROUP BY server_id;"
# a user's effective uuid on a server + node-config match (drift check)
sudo sqlite3 /var/lib/vpnctl/inv.db "SELECT id,uuid,disabled FROM users WHERE id='<user>';"
```
