## 1. Архитектура и Роль Сервиса `vpnctld`

`daemon` (`vpnctld`) — главный управляющий сервис системы (Control Plane).
- Построен на асинхронном стеке **Axum / Tokio / Tower**.
- **Два сетевых интерфейса/контура**:
  1. **Публичный контур подписок**:
     - `GET /sub/{token}`: отдача нативных клиентских конфигураций (sing-box JSON, WireGuard `.conf`, deep-links `vless://`, `tuic://`, `awg://`).
     - `GET /api/v1/app/config/{device_id}`: совместимость с ninitux vpn-router.
     - `GET /api/v1/health`: открытый мониторинговый хелсчек (возвращает статус БД, uptime, версию и `build` SHA).
  2. **Административный контур Web UI**:
     - Префикс `/admin/` (HTML-шаблоны на базе макросов `maud`, HTMX для динамических обновлений, vanilla CSS).
     - Защита: HTTP Basic Auth + Cookie-сессии + строгий CSRF-токен (`handlers/csrf.rs`) для всех POST/DELETE запросов.
     - **Политика отсутствия CLI-онли**: каждое действие администратора доступно через кнопку в Web UI. При возникновении ошибок интерфейс никогда не отправляет оператора в консоль SSH («operator-action policy»).
- **Фоновые поллеры и демоны (Schedulers)**:
  - 10+ независимых воркеров с экспоненциальным backoff и защитой от паники:
    - `node_probe_poller`: SSH-опрос нод (память, диск, uptime, рестарты sing-box, аудит открытых портов).
    - `health_monitor`: отслеживание дрифта SSH-ключей (`fingerprint_drift.rs`), доступности портов, состояния конфигураций.
    - `clash_poller`: опрос Clash API нод для получения детальной статистики по соединениям.
    - `wg_stats_poller`: опрос дампа WireGuard/AmneziaWG (`awg show ... dump`) для сбора переданного трафика и последних рукопожатий (handshakes).
    - `boosty_sync_poller`: периодическая синхронизация с платформой Boosty.
    - `protocol_assurance_poller`: периодическое тестовое сквозное подключение через реальные прокси для замера работоспособности каждого протокола.
    - `quality_poller`: замер latency, jitter и packet loss.
    - `exchange_rate_poller`: фоновое обновление курсов валют ЦБ/биржи для мультивалютного биллинга серверов.
    - `geoip_update_runner`: автообновление баз GeoIP/ASN для аналитики подключений.

## 2. Модуль Wizard & Bootstrap: Добавление Сервера «В один клик»

Флагманская фича `vpnctl` (`daemon/src/wizard_bootstrap/` и `daemon/src/wizard.rs`):
1. **Входные данные**: оператор вставляет в форму IP VPS и пароль root (или SSH-ключ).
2. **Пайплайн развертывания (Server-Sent Events / SSE)**:
   - Шаг 1: Подключение через SSH (с поддержкой fallback пароля и TOFU-проверкой отпечатка хоста).
   - Шаг 2: Генерация выделенного ключа развертывания `vpnctld-deploy` (`/var/lib/vpnctl/.ssh/id_ed25519`) и добавление его в `root@<host>:~/.ssh/authorized_keys` ноды через защищенное экранирование `single_quote`.
   - Шаг 3: Определение архитектуры (`x86_64`, `aarch64`), ОС ноды (Debian/Ubuntu).
   - Шаг 4: Харденинг ноды: отключение root-логина по паролю (`PasswordAuthentication no`), запрет SSH-аутентификации без ключей.
   - Шаг 5: Идемпотентный bootstrap секретов (`bootstrap_server_secrets`): протоколы сервера декларируют требуемые секреты (`server_secret_specs`), визард генерирует X25519 REALITY, WireGuard keypair, PSK, Hysteria obfs и сохраняет в SQLite.
   - Шаг 6: Установка системных ядер (`ensure_installed` для `SingBox`, `AmneziaWg`, `Caddy`, `Xray`).
   - Шаг 7: Генерация, валидация и атомарное применение конфигураций (`apply_config`).
   - Шаг 8: Настройка фаервола (`open_firewall`): открытие только заявленных портов протоколов через `iptables`/`nftables`.
   - Шаг 9: Проверка статуса сервиса (`status`), запись события добавления в `audit_log`.

## 3. Подсистема Подписок и Клиентских Конфигураций

- **Хэндлеры**: `daemon/src/handlers/sub/` и `daemon/src/handlers/vpn_router/`.
- **Логика рендеринга**:
  - Токен валидируется в базе (`find_user_by_sub_token`).
  - Проверка флага `user.disabled`: если пользователь мягко отключен (lapsed Boosty или ручная пауза), выдается пустой список прокси (без ошибки 404, чтобы клиентские приложения не удаляли профиль).
  - Сборка конфигурации: для каждого сервера, на который у пользователя есть грант, вызывается `Protocol::client_config` или `Protocol::share_link`.
  - Поддержка заголовков `Subscription-Userinfo` (отдача оставшейся квоты и трафика в стандарте Clash/Sing-Box).
  - Фиксация доступа: каждый вызов `/sub` логируется в `sub_access_log` с фиксацией IP, GeoIP (страна, город), ASN, User-Agent.

## 4. Административный Интерфейс (`daemon/src/handlers/admin/`)

- `servers.rs`: карточки серверов, статус ядер, нагрузка, кнопки накатки («Deploy»), рестарта, обновления версий ПО нод.
- `server_actions/`: ручные операции (смена портов, включение/выключение протоколов, привязка бастионов).
- `users.rs` & `user_detail/`: список пользователей, выданные серверы, QR-коды для быстрого импорта, кнопка приостановки («Disable/Enable»), история сессий.
- `alerts.rs` & `alert_sink.rs`: система оповещений оператора. Интеграция с Telegram Bot API (`send_message`, авто-редактирование алертов, дайджесты).
- `billing.rs`: финансовая сводка стоимости аренды серверов, даты очередных платежей, расчет себестоимости одного пользователя.
- `boosty.rs`: панель управления интеграцией с Boosty, список подписчиков, ручная привязка аккаунтов, график MRR и выручки.
- `monitoring.rs`: графики активности узлов, трафик по протоколам, выявление шеринга подписок (несколько городов/провайдеров на одном токене).
- `audit.rs`: полный поисковый интерфейс по таблице `audit_log` с JSON-детализацией изменений.
