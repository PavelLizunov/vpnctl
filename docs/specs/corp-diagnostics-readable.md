# Readable Corp diagnostics

## Intent and invariants

The owner requests plain answers, report levels and an immediate solution when
one is established. Keep the existing corp-diagnosis/1 schema, private access,
upload identity, result validation and advisory-only worker. Reports never
authorize commands, installations or policy changes. Existing evidence guards
still separate current, historical and unknown information.

## Presentation contract

1. Short answer: show the report state, a concise owner explanation and received
   date. A ready analysis is not proof that VPN is healthy. A retained older
   result during retry is explicitly identified as the previous result.
2. What to do now: show the validated next_steps_ru prominently before technical
   details. The instructions prioritize a supported remedy for the reported
   current problem; otherwise give one diagnostic next step without promising a
   fix. Advice remains text and is never executed automatically.
3. Why / technical report: native closed details disclose the reasoning and
   findings, then full provenance, original timestamps, report identity and
   evidence references. Preserve every existing evidence/provenance field.

Use the inherited vpnctl theme, clear Russian labels and native keyboard
disclosure. Keep loading, empty, error, unavailable and retained-result states.
No fabricated certainty, model-health badge, autogenerated command or dead fix
button. Follow the owner's anti-slop direction with ENERGY 1/RHYTHM 1/MOTION 1.

## Verification

Existing browser fixtures must exercise summary/action ordering, collapsed
details, keyboard disclosure, evidence/provenance access, historical and unknown
states, retained result during retry, injection text and narrow/desktop layouts.
Existing retry CSRF/session/error gates remain unchanged. No new API is added.
Run formatting/syntax/generated-file/secret checks on the control plane and
independent diff-only review before publication. Exact-source GitHub CI owns
compilation, browser interactions and candidate packaging. Verify the live
read-only scenario and both real report outputs before claiming activation.

## Outcome

Pending implementation and acceptance. Source-confirmed gap recorded before
correction: existing detail view prints all evidence, fingerprints and run IDs
inline ahead of the suggested next step, producing a long technical report even
for an owner who only needs the conclusion and action.

UI review before correction: a retained result can accompany a failed or
unavailable retry, not only a running one. Its banner must distinguish waiting
from a completed unsuccessful attempt. Device names remain untrusted labels;
retain that clarification in the disclosed technical report.

Pre-publication review: the new disclosure summaries need 44px touch targets;
the inherited generic summary rule alone does not guarantee this. Give the two
new summaries an explicit minimum and padding before browser acceptance.
