# Spec: Current TCP path availability and incident evidence

## Intent & invariants
- Detect current loss/recovery from existing completed quality rounds, separately from the 24h quality score. Add no network traffic, credentials, grants, restarts, suppression or subscription changes.
- Report only TCP reachability from the named measurement network; never infer host shutdown, UDP failure, TSPU cause or user blame. Node health and Protocol Assurance remain separate evidence.
- Persist state, incidents and an immutable first-deterioration snapshot. A daemon restart, duplicate sample or operator acknowledgement cannot erase/reopen an incident.

## Interface / data contract
- Public inventory types: `ServicePathStatus { Available, Degraded, Unreachable, Recovering, Unknown }`; `ServicePathState` exposes status, vantage, checked_at, last_success_at. `ServicePathIncident` exposes id, vantage, last_success_at, first_failure_at, confirmed_at, first_recovery_at, recovered_at and diagnostics (`serde_json::Value`). Times are UTC DateTime, optional except checked_at/first_failure_at.
- `SqliteInventory::record_service_path(&ServiceQualitySample, &str target_identity, u64 max_gap_secs) -> Result<()>`: nonempty identity/vantage, positive max gap and valid counts required; sample must not be future dated. Require an existing server. No TCP targets/attempts is unknown, never a full failure. All attempts successful AND all targets available is success; zero successful attempts is full failure; everything else is partial failure.
- State is independent per server + target identity (which includes vantage and declared endpoint population). Ignore a timestamp <= the last processed timestamp for that path, without audit spam. Invalid input fails without mutation. Latest observed path is the current path; changing paths preserves older open incidents without reporting a recovery.
- First partial/full failure opens an incident and sets Degraded. Two consecutive full-failure rounds confirm Unreachable. Partial success interrupts a full-failure streak. Once confirmed, partial success reports Degraded but retains confirmation. One full success with an open episode sets Recovering; two consecutive full-success rounds recover/close it and set Available. A full success without an episode sets Available immediately.
- A gap > max_gap_secs breaks both streaks and clears the pre-gap success bound for a newly starting incident. It never closes an open episode. Unknown samples break streaks but never open/recover incidents. First_recovery_at tracks the start of the current uninterrupted successful recovery streak.
- `current_service_path(&ServerId, DateTime<Utc> now, u64 max_age_secs) -> Result<Option<ServicePathState>>`: None before any record; status Unknown for negative age or age > max_age_secs (inclusive freshness boundary). It is read-only and preserves stored incident state.
- `service_path_incidents(&ServerId, i64 limit) -> Result<Vec<ServicePathIncident>>`: newest first, limit clamped 1..100, empty for unknown server. All public APIs propagate DB/invalid-data errors.
- On first failure, snapshot per-user positive connection observations and byte deltas in 15/60-minute windows ending at last successful round, or first failure when no good round is known; separate transition observations after that cutoff. Include latest node health timestamp/service states and recent server audit action/times, no IPs, destinations, tokens or credentials. A snapshot is immutable as incident progresses; later collection gaps cannot be filled with post-failure evidence.
- Confirmation creates exactly one warning `server.path.unavailable.<incident_id>` in existing admin alerts; confirmed recovery acknowledges that alert and creates a one-shot already-acked recovery event. Existing delivery retry handles opening alerts. Audit actual state transitions/incident/alert mutations; repeated reads/duplicates produce no audit. No external messages are sent directly by this feature.
- Server list/detail show current TCP path status, named network, check time and explicit TCP-only scope. Detail shows persistent incident bounds, confirmation/recovery and expandable diagnostic users. Query failure/old data is unknown. Existing quality charts remain intact.
- Existing assurance templates using revoked identities must not be trusted: archive the invalid is-new templates outside the active directory, so existing missing-template handling reports Unknown. Preserve exactly the owner's three grants.

## Verification
- Spec-derived integration tests: empty state, success, partial/full failure, two-round confirmation/recovery, unknown/zero-target, gap/boundary, duplicate/out-of-order, reopen/restart, independent targets/servers, invalid input, immutable users snapshot and exactly-once alert/audit behavior.
- Admin tests: fresh/old/error states, protocol scope, escaped identities, episode bounds/evidence; no green readiness inferred from successful TCP alone.
- Independent diff review, fmt, canonical cargo gates, `just ci`, secret scan and GitHub CI. Before migration: verified backup/restore drill; production: binary backup, active service, health 200, version/UI and grants verified.
